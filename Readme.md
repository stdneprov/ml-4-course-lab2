# Отчет по лабораторной работе: LLM-сервис для классификации SMS-спама

---

## 1. Бизнес-задача

**Заказчик:** Провайдер сотовой связи / служба модерации сообщений

**Проблема:** Высокий уровень нежелательных и мошеннических SMS-сообщений, которые:
- Снижают доверие пользователей к каналу связи
- Увеличивают нагрузку на службу поддержки
- Создают риски фишинга и финансовых потерь для клиентов

**Цель:** Повышение безопасности и удовлетворённости пользователей за счёт автоматической фильтрации спама в реальном времени.

**Задача:** Разработать proof-of-concept прототип микросервиса на базе LLM для бинарной классификации SMS-сообщений (`spam` / `not spam`).

### 2.2 Развёртывание Docker-контейнера

#### 2.2.1 Базовый образ и зависимости

Использован минималистичный образ `ubuntu:22.04` с последующей установкой:
- **Python 3 + pip** — для запуска FastAPI-приложения
- **curl, wget, git** — для загрузки артефактов и health-check'ов
- **build-essential** — для компиляции зависимостей Python-пакетов

Для повышения надёжности сборки в условиях нестабильного сетевого соединения:
- Заменены репозитории на зеркало `mirror.yandex.ru`
- Добавлены циклы повторов (`for i in 1 2 3`) для `apt-get install`
- Использованы флаги `--connect-timeout`, `--retry` для `curl`

#### 2.2.2 Установка Ollama

Ollama устанавливается внутри контейнера через официальный скрипт:
```dockerfile
RUN curl -fsSL https://ollama.com/install.sh | sh
```

**Проблемы и решения:**
| Проблема | Решение |
|----------|---------|
| Таймауты при загрузке ~500 МБ бинарника | Добавлены повторы и `--connect-timeout 30` |
| Ошибка 404 при парсинге версии из GitHub API | Зафиксирована версия `OLLAMA_VERSION=0.5.7` |
| Несоответствие расширения архива | Использован `.tgz` вместо `.zst` |

#### 2.2.3 Оркестрация через docker-compose

Файл `docker-compose.yml` обеспечивает:
- Проброс портов: `8000` (FastAPI) и `11434` (Ollama)
- Монтирование тома `./ollama_data:/root/.ollama` для сохранения моделей между перезапусками
- Health-check эндпоинта `/health` с интервалом 30 секунд
- Политику перезапуска `unless-stopped` для отказоустойчивости

```yaml
services:
  sms-classifier:
    build: .
    ports:
      - "8000:8000"
    environment:
      - OLLAMA_URL=http://localhost:11434/api/generate
      - LLM_MODEL=Qwen2.5:0.5B
    volumes:
      - ./ollama_data:/root/.ollama
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
```

### 2.3 Реализация FastAPI-сервиса

#### 2.3.1 Эндпоинты

| Метод | Путь | Описание |
|-------|------|----------|
| `POST` | `/generate` | Приём текста сообщения, классификация через LLM, возврат JSON-ответа |
| `GET` | `/health` | Проверка работоспособности сервиса |

#### 2.3.2 Логика классификации

```python
# Формирование промпта с few-shot примерами
prompt = f"""
Ты классификатор SMS-спама. Отвечай строго одним словом: "spam" или "not spam".

Примеры:
- "Привет! Сегодня встречаемся в 18:00?" → not spam
- "Скидка 50% на все товары до конца недели!" → spam
- "Вы выиграли бесплатную подписку! Нажмите здесь!" → spam

Классифицируй строго сообщение: "{request.prompt}"
"""

# Отправка в Ollama и парсинг ответа
response = requests.post(OLLAMA_URL, json={
    "model": MODEL_NAME,
    "prompt": prompt,
    "stream": False,
    "options": {"temperature": 0.1}  # Детерминированный вывод
})
raw_answer = response.json()["response"].strip().lower()

# Нормализация ответа (ВАЖНО: порядок проверок!)
if "not spam" in raw_answer:      # Сначала более специфичный паттерн
    classification = "not spam"
elif "spam" in raw_answer:         # Затем общий
    classification = "spam"
else:
    classification = "unknown"
```

**Критическая ошибка и исправление:**
Изначальная реализация проверяла `"spam" in raw_answer` первой, из-за чего ответ `"not spam"` ошибочно классифицировался как `spam` (подстрока `"spam"` содержится в `"not spam"`). Исправлено изменением порядка условий.

#### 2.3.3 Конфигурация через переменные окружения

```python
OLLAMA_URL = os.getenv("OLLAMA_URL", "http://localhost:11434/api/generate")
MODEL_NAME = os.getenv("LLM_MODEL", "Qwen2.5:0.5B")
```

Это позволяет гибко менять модель и адрес Ollama без изменения кода.

### 2.4 Скрипт инициализации (init.sh)

Скрипт обеспечивает корректный порядок запуска:
1. Проверка, запущен ли уже процесс `ollama`
2. Запуск `ollama serve` в фоновом режиме
3. Ожидание готовности API (до 30 попыток с интервалом 2 сек)
4. Автоматическая загрузка модели, если она отсутствует
5. Запуск FastAPI через `uvicorn`

```bash
# Ожидание готовности Ollama
for i in {1..30}; do
    if curl -s http://localhost:11434/api/tags > /dev/null 2>&1; then
        break
    fi
    sleep 2
done
```

## 3. Тестирование сервиса

### 3.1 Тестовый скрипт (requests.sh)

Минималистичный bash-скрипт с использованием `curl` и `jq` для валидации ответов:

```bash
run_test() {
    local name="$1" prompt="$2" expected="$3"
    response=$(curl -s --max-time "$TIMEOUT" -X POST "${BASE_URL}/generate" \
        -H "Content-Type: application/json" \
        -d "{\"prompt\": \"$prompt\"}")
    answer=$(echo "$response" | jq -r '.answer // "error"')
    [[ "$answer" == "$expected" ]] && echo "✅ $name" || echo "❌ $name"
}
```

### 3.2 Тестовые сценарии

| № | Тип сообщения | Текст | Ожидаемый ответ |
|---|---------------|-------|-----------------|
| 1 | Личное сообщение | "Привет, как дела?" | `not spam` |
| 2 | Агрессивный спам | "ВЫ ВЫИГРАЛИ АЙФОН!!! ЖМИ СЮДА!!!" | `spam` |
| 3 | Сервисное SMS | "Ваш код подтверждения: 12345" | `not spam` |
| 4 | Фишинг | "Карта заблокирована. Подтвердите: http://fake.ru" | `spam` |
| 5 | Кредитное предложение | "Получите кредит без проверки прямо сейчас!" | `spam` |
